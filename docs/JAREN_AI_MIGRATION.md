# Jaren AI ownership and qualification

Jaren supplies independent generic engines, contracts and complete editors.
Tangle owns the model, context and agent mechanisms, their Jaren integrations,
the reusable assistant, and the Pages adventure. The current foundation is
[Jaren 0.86.0](JARENJS_INTEGRATION.md); the qualification below retains the
0.84.3 migration and TypeScript-conversion receipts. The original [close-out receipt](migrations/jaren-ai/closeout.json)
records the committed 0.84.0 migration; its foundation-manifest hash describes
the bytes at Tangle commit `2fcb6b0dfbd3b5f390af8d8040e162d080653945`.
The [0.84.3 qualification](migrations/jaren-ai/qualification-0.84.3.json) records
the subsequent local update. Registry publication remains a separate, manual
author action.

## Editors, assistant and browser protocol

Both sites mount one complete Jaren-owned Studio/Data/Flow implementation.
Tangle owns thin routes, seeds, downloads, storage identities and worker
initialization. Its authors validate and publish through the same public
revision checks as manual edits. Invalid or stale candidates preserve human
work. Project runs return settled host results. State-only app updates preserve
the mounted stage, focus and selection; structural edits advance its stage
revision. Data keeps unfinished buffers across deactivation and resumes through
its owned worker lifecycle. Real SQLite storage, migrations, independent query
replies, live streams, startup failure/retry and late disposal are exercised.

The private Pages app pins `@sqlite.org/sqlite-wasm@3.53.0-build1`, verifies its
real installation and emits two worker entries, WASM and the OPFS proxy. This
initializer exception never enters a published package. Jaren's public driver,
contract, transport, controllers and scoped styles remain the implementation.
See [Pages host requirements](migrations/jaren-ai/PAGES.md).

Assistant mounts own their listeners, transcript, requests and writer lifecycle.
Cancel/dispose fences late provider replies, tool calls and child authors.
Storage failures remain visible. Game exit cancels pending NPC dialogue;
scripted play, victory, save/load, localization and no-key/provider-failure
paths remain available. Optional tools without host services return explicit
refusals. Jaren exposes only its ordinary site/editor operations through plain
contracts, without an assistant or model configuration.

Both hosts use the same `@jarenjs/contract/webmcp` adapter. Automatic discovery
chooses a usable `document.modelContext`, then `navigator.modelContext`;
getters are guarded and an alias registers once. An own `options.context`,
including `null` or `undefined`, is authoritative. The Tangle wrapper's legacy
positional `undefined` means automatic discovery. Supported methods are current
`registerTool` and legacy `provideContext`, independently of which root exposes
them. Await `binding.ready`; a pending registration is never reported as success.
Refusal or partial mutation does not trigger fallback into a second root.
Disposal owns rollback and callback deactivation, including pending and late
registration. Without a native removal API, the result reports that limitation;
foreign registrations are never cleared. Explicit refresh/focus can detect
later availability. Back/forward-cache suspension preserves ownership, and
final page departure releases it.

Stock headless Chromium `149.0.7827.55`, Firefox `151.0` and WebKit `26.5` on
localhost, without feature flags or an origin trial, expose neither root.
Native integration is therefore **unavailable**, separately from the passing
injected compatibility matrix and ordinary UI checks. Unknown future protocol
changes are not claimed compatible: requalify discovery, methods, asynchronous
results, partial refusal and cleanup with both-root tests before supporting one.

## Persisted data and checkpoint limits

Existing schema IDs, replay/cache bytes, embedding identities, budgets and
ordinary ledger/memory formats remain stable. Storage is origin-scoped. The
[explicit transfer procedure](migrations/jaren-ai/BROWSER_DATA.md) exports
selected non-secret transcript, ledger, game, project and experiment slots from
the old origin and imports only into empty or identical destinations. It
preflights conflicts, reports partial writes, and repeats without writes.
Credentials and provider settings are excluded. No automatic cross-origin
access, credential migration or global transaction across localStorage writes
is promised. Pages conservatively uses one ledger writer on every browser.

MAS executable identity is
`tangle-mas/3:flow/<version>:models/<version>:context/<version>:agents/<version>:<registry>`.
Mismatched executable checkpoints are refused with `TMAS2002` before effects or
writes; repeating the attempt leaves the checkpoint intact. This includes a
0.84.3 Flow execution identity when the runtime now uses Flow 0.86.0, as well as
legacy executable identity formats. Ordinary records
remain readable. No automatic legacy executable conversion is claimed.

## Scoped quirk audit and release state

Confirmed migration defects, with reproductions and fixes:

- Document-only browser discovery, asynchronous readiness and ownership were
  incomplete; the shared adapter and both hosts now retain the full matrix.
- Public editor publication could lose raw Data input or restart state-only
  Studio changes; real browser and public-operation regressions retain buffers,
  stage identity, focus and results.
- Assistant cancellation and closed storage ownership could accept late work;
  controller/storage tests and browser cases now fence it and surface failures.
- A persisted `pagehide` consumed final cleanup; the three-engine reproduction
  now retains the handler until final departure.
- Dirty capture packed a deleted Studio author declaration; clean reconstruction
  refused the archive, and capture now cleans before emitting declarations.
- Artifact verification admitted extra files/edges and bootstrap checked pins
  too late; focused negative fixtures now refuse these inputs without repair.
- CI installed before artifact bootstrap, Pages metadata described candidate
  input as registry input, and publication lacked an explicit candidate-mode
  refusal; setup, metadata and publication now enforce the recorded mode.
- Manual assistant tooling remained in Jaren; it is received in Tangle with
  scripted browser and four-viewport evidence.

Confirmed adjacent findings and dispositions:

- Existing benchmark-only dependency advisories remain under Jaren's documented
  dependency audit policy; no runtime dependency was added to address them.
- Historical live authoring, depth and retrieval losses remain measured losses.
  Their open obligations belong to [the AI mechanism roadmap](AI-MECHANISM-ROADMAP.md).
- Native WebMCP and WebKit OPFS availability are tested platform limitations.
  Provider configuration and a future protocol qualification remain host work.

Checked and dropped suspicions:

- The pen's error import might retain a query/runtime engine. The measured
  isolated bundle retains nine authoring modules and zero excluded engine bytes;
  no new foundation API was invented for that suspicion.
- Missing declarations during one concurrent build were caused by two commands
  replacing the same generated directories. Sequential full gates preserve
  strict checks; no declaration stub or skipped library check was introduced.
- Changed MAS report hashes might indicate a functional regression. Regenerated
  identity/handoff reports preserve all 11 positive and seven negative oracles.
- Contract projection, export ZIPs, vectors and generic grammar profiles are
  independent of AI and remain in Jaren with their assertions.
- Generic editor duplication, silent storage failures, package cycles, private
  runtime imports, orphan worker/styles and unexecuted inherited JS tests were
  checked through source, operation, browser and packed-consumer gates.
